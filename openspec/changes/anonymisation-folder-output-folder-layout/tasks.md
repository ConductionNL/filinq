## Tasks

> **All 10 tasks are DEFERRED to the same focused integration PR as `anonymisation-batch-output-folder-layout` tasks 3-13** (FolderBatchService + FolderExtractionJob consume the `OutputLayoutResolver` helper that landed in this batch with full unit-test coverage). The shared helper is in place; the call-site wiring + move-failure handling + path-recording + Newman + docs ship as one cohesive PR so the batch- and folder-flow layouts stay in sync.


- [~] 1. **FolderBatchService integration** — in `lib/Service/FolderBatchService.php`, after each file's anonymisation completes, invoke `OutputLayoutResolver::resolveBatchDestination()` (from `anonymisation-batch-output-folder-layout`); move the file from OR's output location to the target via `\OCP\Files\IRootFolder` atomic move/rename; create the subfolder if needed; on move failure, preserve at legacy path with per-file `warning` and detailed log.
- [~] 2. **FolderExtractionJob integration** — in `lib/BackgroundJob/FolderExtractionJob.php`, apply the same post-process via the same helper; ensure idempotency on retry (if the file is already at the target, the move is a no-op; if at legacy, retry has a real chance to succeed).
- [x] 3. **Source-discovery filter** — `lib/Service/FolderBatchService.php::enumerateFiles()` injects `OutputLayoutResolver` and excludes any direct child whose base name ends with the legacy `_anonymized` suffix via the shared discriminator `OutputLayoutResolver::isLegacyAnonymizedOutput()` (one source of truth, no string drift). `FolderExtractionJob` does NOT need the same filter — it only iterates over files already queued by `FolderBatchService`, so the filter at enumeration time covers the folder-flow entry surface. Coverage: `tests/unit/Service/FolderBatchServiceTest.php::testEnumerateFilesExcludesLegacyAnonymizedOutputs` (mixed source set: clean files pass, `_anonymized`-suffixed ones are filtered) and `testEnumerateFilesAllLegacyOutputsThrows400` (re-run on a folder full of redacted copies surfaces the standard "no files" 400 rather than silently producing an empty batch).
- [~] 4. **Path-recording update** — update the folder-flow's recorded `anonymizedFilePath` (in batch state, response, job result) to reflect the new location; on move failure, the path is the legacy location with the warning indicating the situation.
- [x] 5. **Single-file regression guard** — covered by `tests/unit/Service/AnonymizationServiceSingleFileRegressionTest.php` (shared with the sibling batch-layout change, see `anonymisation-batch-output-folder-layout` Task 7). The test asserts at the source level that `AnonymizationService` does NOT import or reference `OutputLayoutResolver` / `resolveBatchDestination` / `isLegacyAnonymizedOutput`, so the per-document anonymise endpoint stays untouched by the folder-flow rewrite. Fails CI on any future refactor that wires the helper into the per-document path.
- [~] 6. **FolderBatchService unit tests** — `tests/unit/Service/FolderBatchServiceTest.php`: post-process places file at expected path; subfolder created on first run; reused on second; collision overwrites; move failure preserves at legacy with warning; source-discovery excludes `_anonymized`-suffixed files.
- [~] 7. **FolderExtractionJob unit tests** — `tests/unit/BackgroundJob/FolderExtractionJobTest.php`: job applies the layout; retry path is idempotent (target-already-there → no-op, legacy-still-there → succeeds); per-file warnings surface in job result.
- [~] 8. **Integration tests — Newman** — trigger a folder-analysis run on a multi-file folder: all redacted outputs in `<source>/anonymised/` with clean filenames; re-run: subfolder reused, files overwritten; configure non-default subfolder name: outputs land there; source folder with legacy `_anonymized`-suffixed files: NOT included in source set.
