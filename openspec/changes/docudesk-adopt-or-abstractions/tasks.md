# Tasks — docudesk: adopt OR abstractions

- [ ] 2. **Lifecycle annotation — batch-correspondence** — in `lib/BackgroundJob/BatchCorrespondenceJob.php` (five literal `'status' => ...` writes around lines 111/162/168/186/199), define `x-openregister-lifecycle.states[]` (`pending`, `processing`, `success`, `error`, `completed`) on the batch-correspondence schema and replace inline writes with OR's lifecycle transition API.
- [ ] 3. **Lifecycle annotation — signing + stats/batch** — add `pending`, `signed`, `rejected`, `expired` to the signing-request schema (`NativeSigningProvider.php:105`, `ValidSignProvider.php:114`); fold the remaining literal status writes in `FileEntityStatsService.php:126`, `BatchUploadService.php:48`, `BatchStateService.php:33` into the same per-schema annotations; document allowed transitions + auth requirements and reference `hydra-gate-orphan-auth`.
- [ ] 4. **Notification annotation** — identify all direct `notificationManager->notify()`/`setSubject()` call sites under `lib/Service/` (signing providers + batch-correspondence job); convert to declarative `x-openregister-notifications` triggers keyed on the Phase 2/3 lifecycle transitions; pull notification copy through `i18n-source-of-truth` (per Task 9).
- [ ] 5. **Archival annotation** — add `x-openregister-archival.retention: P10Y` to the signing-audit schema (replacing the Archiefwet comment in `SigningAuditService.php:7`); add `x-openregister-archival` to report/template/entity schemas in `openspec/specs/document-register/spec.md` matching Archiefwet selectielijst categories; add shorter-retention `x-openregister-archival` to batch-correspondence + anonymization-result schemas (justify the chosen periods in the spec).
- [ ] 6. **Calculation annotation** — migrate anonymization-confidence, entity-density, redaction-coverage on the report schema to `x-openregister-calculations`; migrate metadata-enrichment outputs (classification, language-detection, summarization) to calculations; migrate OCR confidence + extracted-text-length on the file-attachment schema (raise an OR PR if the schema is upstream).
- [ ] 7. **Document-register spec rewrite** — rewrite `openspec/specs/document-register/spec.md` to define report/template/entity schemas as full JSON Schema (drop `properties: []`), add Phase 4 `x-openregister-archival`, mandate validation through OR's schema validator.
- [ ] 8. **Anonymization + batch spec rewrites** — rewrite `openspec/specs/anonymization/spec.md` to replace custom file ingest with OR File Attachments, replace custom entity extraction with OR `TextExtractionService`, and re-express anonymization as a calculation annotation; rewrite `openspec/specs/batch-anonymization/spec.md` to replace `ICache` per-file state with child-object lifecycle annotations and delegate scheduling to OR Background Jobs.
- [ ] 9. **(P2) Metadata-enrichment spec rewrite** — rewrite `openspec/specs/metadata-enrichment/spec.md` to declare enrichment as a calculation annotation rather than a custom service.
- [ ] 10. **Hardcoded magic-number cleanup — OCR + templates** — promote `OcrService::DEFAULT_LANGUAGES`, `OcrService::DEFAULT_DPI`, and `TemplateService::LOCK_TIMEOUT_MINUTES` to admin-config keys (`docudesk.ocr.default_languages` = `nld+eng`, `docudesk.ocr.default_dpi` = `300`, `docudesk.templates.lock_timeout_minutes` = `15`) preserving defaults.
